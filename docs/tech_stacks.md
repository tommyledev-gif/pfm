# PFM – Tech Stack

> Last updated: 2026-07-30  
> Scope: Mobile App + Go Backend + Python AI Service

---

## Architecture Overview

```
[Flutter App]
      │  REST (HTTPS)
      ▼
[Go Backend API]  ──→  [PostgreSQL]
      │  REST (internal)
      ▼
[Python AI Service (FastAPI)]
```

AI service is a **separate microservice** — not embedded in the Go backend.  
Backend handles all business logic + data ownership; AI service handles LLM calls + ML inference only.

## 1. Mobile App (Flutter)

| Layer | Library | Version | Notes |
|-------|---------|---------|-------|
| Framework | Flutter (Dart) | stable | Cross-platform, native perf, local build (no EAS dependency) |
| State management | Riverpod | 2.x (code-gen) | Type-safe, doubles as DI — no need for get_it |
| Routing | go_router | latest | Official, deep-link support (activation link from email) |

| Networking | dio + retrofit | latest | Retrofit generates type-safe client from API annotations |
| HTTP client type | Dart generated client | — | Generated by openapi-generator from openapi.yaml |
| Charts | fl_chart | latest | Expense trend charts |
| Forms | flutter_form_builder | latest | Less boilerplate than reactive_forms for CRUD forms |
| Secure storage | flutter_secure_storage | latest | JWT access + refresh token storage |
| Config/env | envied | latest | Compile-time env vars (BASE_URL, etc.) per environment |

**Dropped:** get_it (covered by Riverpod), reactive_forms (replaced by flutter_form_builder)

## 2. Backend — Go

| Layer | Library | Notes |
|-------|---------|-------|
| Web framework | Fiber v2 | Express-like, high performance |
| DB driver | pgx/v5 | Native PostgreSQL driver, used by sqlc |
| Query layer | **sqlc** | Type-safe Go code generated from raw SQL — do NOT use GORM |
| Database | PostgreSQL 16 | Relational, supports aggregation/reporting, pgvector extension |
| Migrations | golang-migrate | SQL file-based, idempotent |
| Auth | golang-jwt/jwt v5 | Access token (15m) + refresh token (7d) |
| Validation | go-playground/validator v10 | Struct-tag validation, OWASP input safety |
| Logging | Zap (uber-go/zap) | Structured JSON logging — never log sensitive fields |
| API spec generation | **oapi-codegen** | API-first: write openapi.yaml → generate server boilerplate |
| Rate limiting | Fiber built-in limiter | Applied on auth endpoints from day 1 |
| Password hashing | bcrypt | Cost = 12 |
| Secure token | crypto/rand | For invite tokens — NOT UUID |

**Why sqlc over GORM:** GORM hides N+1 queries, has zero-value gotchas, and loses type safety on complex aggregations. Expense tracker needs GROUP BY, SUM, date range — raw SQL is the right tool.

**Why oapi-codegen over Swaggo:** API-first means the spec is the source of truth. Write `openapi.yaml` → generate Go server interfaces → generate Dart client. Swaggo generates docs *after* the code, inverting the dependency.

## 3. AI Service — Python

| Layer | Library | Notes |
|-------|---------|-------|
| Framework | FastAPI | Async, auto OpenAPI docs, same mental model as Fiber |
| LLM (primary) | **Groq SDK** | Free tier, fast inference — budget constraint |
| LLM (fallback) | Anthropic SDK (Claude) | For complex reasoning if Groq insufficient |
| Background tasks | FastAPI BackgroundTasks | Sufficient for MVP — add Celery+Redis when needed |
| Vector search | pgvector (Postgres extension) | Enabled in migration; use when RAG is needed — no separate vector DB |
| Internal transport | REST over Docker network | Simple; switch to gRPC if latency matters post-MVP |

**Deferred:** Celery + Redis (add when async categorization pipeline becomes real workload)

**AI Service responsibilities (MVP):**
- Auto-categorize transaction from text input / receipt OCR
- Chatbot: "tháng này tui tiêu bao nhiêu cho ăn uống?"
- Anomaly detection / spending alerts

## 4. Data Conventions

| Rule | Detail |
|------|--------|
| Money | `BIGINT` (integer cents/xu) or `NUMERIC(19,4)` — **never FLOAT** |
| Timezone | Store UTC in DB (`TIMESTAMPTZ`), convert to local at client |
| IDs | `UUID v4` via `uuid_generate_v4()` |
| Soft delete | `deleted_at TIMESTAMPTZ NULL` — no hard deletes on financial records |
| Categories | Seed system defaults (`null` user_id); users can add custom ones |

## 7. Tech Decision Log

| Decision | Chosen | Rejected | Reason |
|----------|--------|----------|--------|
| Query layer | sqlc | GORM | Type-safety, explicit SQL, no N+1 magic |
| API design | API-first (oapi-codegen) | Code-first (Swaggo) | Spec drives server + client codegen from same source |
| Forms (Flutter) | flutter_form_builder | reactive_forms | Less boilerplate, wider ecosystem |
| Vector DB | pgvector (Postgres extension) | Qdrant | Avoid extra service; reuse existing DB |
| LLM | Groq (primary) | Anthropic-only | Budget — Groq free tier is sufficient for MVP |
| Background tasks | FastAPI BackgroundTasks | Celery+Redis | Defer complexity until real async workload exists |
| Auth token gen | crypto/rand | UUID | UUIDs are not cryptographically secure for security tokens |
